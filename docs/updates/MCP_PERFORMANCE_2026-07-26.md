# MCP 读取性能与内存边界优化记录（2026-07-26）

## 基线与问题

- 基线提交：`54979b9f043b2c92d73e9976f8b978ac11c2917d`。
- `read_node_context` 即使未请求后代，也会读取并解析完整导图快照，再加载导图全部节点建立索引。
- 文档和导图快照缓存只限制为各 64 条，没有字节上限。大快照长期累积时，条目数上限不能有效约束内存。
- 真实 292 节点导图完成一次默认读取后，长期 stdio 服务进程基线约为 54.2 MB 工作集、63.1 MB 私有内存。
- Windows 辅助客户端缺少 `search_nodes` 的直接 `--query` 参数，仍可能迫使调用方使用易受 shell 转义影响的 JSON 参数。

## 本次改动

- 默认 `read_node_context` 改为 MySQL/TiDB 递归 CTE，只读取目标节点到根节点的路径，并在同一查询中计算每个返回节点的直接子节点数。
- 只有显式传入 `includeDescendants: true` 时才加载整张节点表并构造有界子树。
- 默认节点读取不再解析完整导图快照；需要完整导图时继续显式调用 `read_current_mindmap`。
- 外部 stdio MCP 的文档快照缓存限制为最多 4 条、合计最多 2 MiB；导图快照缓存限制为最多 1 条、合计最多 6 MiB。超过单缓存字节上限的快照不会进入缓存。
- Electron 文档快照缓存限制为最多 4 条、合计最多 2 MiB，并复用于 MCP 文档正文读取。
- 本地辅助客户端新增 Windows 安全的 `--query` 直接参数。

## 真实验证

验证对象为真实知识库“金融市场基础知识”、真实 292 节点导图和真实节点“风险性”，未创建、修改或删除任何数据库数据。

- 默认节点读取正确返回目标节点、5 级祖先、真实子节点数和两条关联文档摘要。
- 单次诊断调用（包含 Node 进程启动、MCP 初始化、MySQL 连接和关闭）耗时约 294.1 ms，输出 3537 个字符。
- 长期 stdio 会话预热后连续 20 次默认读取：P50 3.37 ms，P95 4.11 ms，最小 2.68 ms，最大 4.34 ms。
- 同一长期会话连续 500 次真实读取：平均 3.84 ms；第 1 次到第 501 次之间工作集增加 6.5 MB、私有内存增加 4.6 MB。该数据包含 V8 运行时堆扩展；快照缓存本身具有固定字节上限。
- 显式子树读取以 `maxDepth=2`、`maxNodes=20` 返回真实 20 个节点，并正确报告总后代 21、结果已截断。
- `--query "风险性"` 正确命中唯一真实节点。
- `npm run build` 完整通过，包括 MCP、数据边界、文档、导图、TypeScript、Vite 和 Electron 构建检查。

## 影响范围与兼容性

- 不改变 MCP 工具 ID、默认目标校验、写入权限或数据库数据结构。
- 不执行数据库迁移，不写入真实知识库数据。
- 默认节点读取对依赖完整导图快照才能计算的 `nodeKind`、`summary` 扩展字段返回 `null`，保持字段形状但不为此加载大快照；完整导图读取能力仍由 `read_current_mindmap` 保留。
- 显式后代读取保持原有完整节点投影路径，因此现有子树结果和截断语义不变。
